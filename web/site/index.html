Why SELECT

Every language in your stack has real tooling. Except SQL.

You have completion, go-to-definition, lint on save, a formatter and twenty years of git history in the editor you already like. Then you open your SQL client, and it is a text area with a Run button, a connection tree, and a tab called Script-14.sql that nobody will ever read again.

We do not think that is a missing feature. It is a missing shape. SQL is code. It gets reviewed, refactored, blamed, reverted and rewritten by whoever picks up the ticket next. It should live where the rest of the code lives, and be edited by something that understands it.

The mature clients are not badly built. They are built for someone else. They grew up serving the person who administers the database, and the developer writing SQL between two commits was never their customer.

We only build for you. Every choice here follows from that: files instead of a workspace database, git instead of sharing, a keyboard instead of a wizard, one grant instead of an admin ticket.

01 · The editor

It knows your schema before you do

Point it at Postgres, MySQL or SQLite and it introspects the whole schema. Completion is real: tables, columns, types, keys, not a keyword list. So is the lint: your SQL is parsed and checked against that schema, so it catches the column that does not exist, the id that is ambiguous across two joins, the CTE you stopped using and the = NULL that silently matches nothing. Your own rules go in a file in the repo, scoped by path, so the rule your team agreed on is the rule everyone gets.

Agents

Give your agent a key, not the keys

You already point Claude Code and Cursor at your repo. Point them at your database the same way. The MCP server exposes seven tools and nothing else: no shell, no filesystem. An API key carries roles, and those roles are exactly what the model can touch.

MCP server & API keys →

What reaches our servers

Almost nothing of yours reaches us.

Your queries, lint rules and themes are files in your workspace, and our servers have no idea they exist. Credentials reach us only if you turn on the proxy, encrypted field by field and never handed back to a client. Keep a connection local and we never see it.

What we do hold is what runs through us, a proxied query or an MCP call, plus your roles and groups, so a grant you make on one machine is enforced on every other.
